# Landing SEO: "Tu software en nuestros kioscos autoservicio"

> Investigación de keywords y propuesta de estructura para la landing orgánica dirigida a desarrolladores y empresas de software sin fabricación propia.
> Fecha: 18/11/2026 · Estado: **propuesta pendiente de validar** (Fase 2). La landing no se ha creado todavía.

---

## 1. Limitaciones de la investigación

- **Volúmenes de búsqueda:** no he encontrado ninguna fuente pública fiable con volúmenes para estas keywords en España. **Todos los volúmenes aparecen como "sin dato".** Se pueden sacar en 10 minutos desde el **Planificador de palabras clave de Google Ads** (TCSystems ya tiene cuenta activa) o con Semrush o Ahrefs, filtrando por España. Lo dejo como tarea antes de publicar.
- **SERP:** las búsquedas se han hecho con un buscador web genérico, no con Google.es en una sesión española. Sirven para ver **qué tipo de páginas y qué competidores aparecen**, pero no son un ranking exacto de Google.es. Tampoco he podido extraer directamente el bloque de "Otras preguntas de los usuarios": las preguntas de la FAQ (§6) salen del contenido que cubren las páginas que aparecen y de las dudas típicas de cada perfil, no de una captura real del PAA.

**Cómo son las páginas que compiten:**
- La mejor referencia temática (TermBridge, OEM/ODM) tiene unas **700-800 palabras visibles**, con un H1, H2 de "niveles de servicio", escenarios por sector, arquitectura (carcasa, periféricos, frontera software/integración, fabricación) y una checklist del proyecto.
- Los competidores españoles posicionan con **PDF de catálogo** o fichas de producto con poco texto y sin FAQ.
- **Objetivo para nuestra landing:** entre 1.200 y 1.600 palabras, con secciones escaneables, una FAQ de 7-8 preguntas y schema. Con eso cubrimos más que cualquier resultado actual en español.

**Riesgo de canibalización detectado:** `/kioscos-autoservicio-espana` (landing de anuncios, indexable) ya trabaja "fabricante español de kioscos de autoservicio". Por eso la keyword principal de la nueva landing **no debe** ser "fabricante de kioscos autoservicio" a secas: tiene que llevar el modificador "integrar software" o "integradores".

## 4. Propuesta

### Keyword principal
**`kioscos autoservicio para integrar software`**

Por qué esta y no otra:
1. Recoge el mensaje del cliente ("tu software en nuestros kioscos").
2. No canibaliza `/kioscos-autoservicio-espana`.
3. El SERP en español no tiene ninguna página dedicada a esta intención.

### Secundarias (8)
1. fabricante de kioscos autoservicio a medida
2. fabricante de terminales autoservicio a medida
3. kiosco autoservicio para integradores
4. hardware para software de gestión
5. integrar software en kiosco autoservicio
6. kiosco autoservicio OEM / marca blanca
7. hardware autoservicio para TPV
8. kiosco autoservicio con API / SDK *(solo si TCSystems confirma que ofrece SDK o drivers documentados → [PENDIENTE CLIENTE])*

### URL
**`/integradores-kioscos-autoservicio`**

⚠️ **Nota técnica:** `components/ConditionalLayout.tsx` trata como landing de anuncios **cualquier ruta que empiece por `/kioscos-autoservicio`** (comprueba `startsWith`). Una URL como `/kioscos-autoservicio-integradores` se quedaría sin Header ni Footer y heredaría el comportamiento de las landings de pago. Por eso propongo `/integradores-kioscos-autoservicio`, que mantiene las keywords en la URL sin tocar la lógica de las landings de anuncios.

Alternativas: `/hardware-autoservicio-para-software` o `/tu-software-en-nuestros-kioscos`.

### Title (58 caracteres)
`Kioscos autoservicio para integrar tu software | TCSystems`

### Meta description (≈143 caracteres)
`Fabricamos el kiosco, tú pones el software. Kioscos autoservicio de catálogo o a medida para integrar tu software en cualquier sector. Hablemos.`

### H1
**`Fabricante de kioscos autoservicio para integrar tu software`**

- Empieza por la keyword principal ("kioscos autoservicio para integrar tu software") y además lleva la secundaria más fuerte ("fabricante de kioscos autoservicio"). Dice exactamente qué es la página.
- El lema comercial "Tu software en nuestros kioscos, para cualquier tipo de establecimiento" **no va en el H1**. Va como antetítulo (pastilla) o como primera frase del subtítulo, porque no tiene keyword y no posiciona.
- El title y el H1 no tienen que ser idénticos. El title se queda en "Kioscos autoservicio para integrar tu software | TCSystems" para no pasar de 60 caracteres.

### Formulario
Reutilizo `ContactForm`, que ya envía a `/api/contact`, guarda en BD y manda los emails. Propongo añadirle **props opcionales** para mostrar en esta landing:

- tipo de software (texto),
- sector (selector),
- número aproximado de instalaciones (selector por rangos).

"Empresa" ya existe. Los campos nuevos se concatenan en el mensaje (`project`), así que **no cambian ni la API ni la BD** y el resto de páginas que usan `ContactForm` no se ven afectadas. El `productName` sería "Integradores de software", para identificar los leads en el panel `/admin`.

### SEO técnico
- `layout.tsx` con metadata (title, description, canonical, OG, Twitter) siguiendo el formato de `/parkings`.
- JSON-LD: `Service` (`audience: BusinessAudience`, "Empresas de software e integradores"), `FAQPage` mediante `faqPageSchema()` y `BreadcrumbList`.
- Alta en `app/sitemap.ts` con prioridad 0.8.
- Enlazado interno:
  1. Header → desplegable "Servicios".
  2. Footer → columna "Servicios".
  3. Home → enlace desde `SectorsSection` o `CTASection` ("¿Desarrollas software? Intégralo en nuestros kioscos").
  4. Opcional: un párrafo en `/quienes-somos`.
- Imágenes con `next/image` (lazy por defecto, `priority` solo en el hero), en `.webp` y con `alt` descriptivos.
